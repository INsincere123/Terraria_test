# 灾厄深渊免疫验证

## 实现范围

- 终极盔甲完整功能套装、神之心各自通过 `AbyssImmunityEffect.Apply` 激活每玩家的共享标志，双来源不重复结算照明。胸甲幻影龙与腿甲炮台开关不影响深渊免疫。
- 仅灾厄加载时设置 `ignoreWater`；该移动效果适用于普通水域，不改变 `wet`、区域判定、碰撞、翼力或位置。
- 深渊内按 Marivinium 满档参数增加照明：`abyssDarkness -= 1.5`、`abyssPlayerGlowMultiplier += 2`、`abyssFlashlightWidthMultiplier += 0.5`。
- `AbyssVisionSystem` 在本地玩家装备生效且位于深渊时，对传播完成的光照结果提供中性环境光下限（RGB 0.5），覆盖当前画面，保留适度明暗层次；移除单点浅蓝发光，避免仍然只照亮角色附近。保留更亮的光源、Boss 遮罩与最终亮度修正。Color/White 在 `LightingEngine.ProcessBlur` 的 `LightMap.Blur` 完成后批量补光；Retro/Trippy 在现有结果复制循环中仅补绘制通道，不更改 GPU 资源或全局光照参数。
- 灾厄照明汇总之后、深渊环境扣防/扣氧之前条件返回，补满呼吸，清理深渊呼吸计时、死亡标志与相关统计。
- 只修改 `UpdateBadLifeRegen` 中第一层环境水中毒的水下条件和深渊离水伤害的条件。保留海灾 Boss 的独立中毒入口、其他战斗减益、硫磺海区域行为以及深渊传送惩罚。
- 深渊环境遮罩与独眼巨鹿共用 `darknessIntensity`；独眼巨鹿场地仍在绘制时保留该值，防止屏蔽其累积战斗黑暗。
- 成员签名或 IL 不匹配时记录一次加载警告并停用对应兼容项，不修改未知分支；卸载释放环境与光照 ILHook 及全部反射缓存。

### 视野修正

- 用户运行反馈：原实现和 Marivinium 都只提供较小范围的角色照明，不能使深渊无光区域可见。说明角色光源与遮罩参数不足以保证整个画面的视野。
- 当前 `client.log` 选择的是本地 `Mods/2026.6CalamityMod.tmod`（2.2.4），其哈希与 Workshop 同版本不同；已提取并针对实际本地程序集重新运行原有 IL 匹配、版本漂移拒绝和钩子安装/释放检查，全部通过。
- 最初补光在原版光照扫描后、正常传播前执行；性能优化后改为传播结束后、最终亮度修正前执行，只作用于本地装备者的深渊画面。光照缓冲按游戏处理周期刷新，卸装或离开深渊后需等待一次正常扫描恢复。
- 修正后 `ResolveReferences;CoreCompile` 通过。用游戏实际 `LightMap` 类型在独立验证进程中检查：扫描区远端无光单元得到当时的 0.75 环境光、更亮的原有颜色通道保留、扫描区外及世界边界不被改写；随后按用户要求将环境光下限调为 0.5，并重新编译检查。未执行游戏画面验证。

### 补光性能优化

- 不再在 `TileLightScanner.ExportTo` 扫描阶段填亮工作缓冲，避免补光扩大原版传播的有效处理范围。没有向逐格 `GetColor` 查询增加钩子。
- 现代光照每次传播完成后补一次结果缓冲；旧式光照利用既有复制循环补 `R/G/B`，不写传播用的 `R2/G2/B2`，不增加第二次遍历。
- 本地玩家的装备/深渊状态每游戏 tick 判断一次，逐格处理只读取缓存；现代光照反射读取两个缓冲字段仅在一轮传播结束时执行。
- 对当前实际游戏程序集检查现代补丁紧接 `LightMap.Blur`、旧式补丁仅匹配六个绘制通道复制入口，原有指令保留；两种钩子均在独立进程成功安装/释放。真实 `LightMap` 的 0.5 下限、较亮通道保留、世界边界和状态清理检查通过。
- 独立 CPU 微基准使用实际 `LightMap`，216×151 无光网格、每组 10 次、5 组中位数：扫描阶段补光后传播约 1.411 ms，传播后补光约 1.287 ms。该样本只验证处理路径，不能代表实际深渊场景的 FPS 或保证同等提升。
- 仍需在同一深渊位置、光照模式、分辨率与缩放下对比游戏帧率；同时检查镜头移动和卸装后的正常刷新。编译与隔离程序集检查不能替代这些验证。
